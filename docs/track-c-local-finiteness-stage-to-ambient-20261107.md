## Exact hypotheses and mathematical results

Let `S` and `T` be (not necessarily unital) rings and let
`f : S →ₙ+* T` be any non-unital ring homomorphism with finite source
`S`. If the coordinates of a finite tuple `x` in `T` lie in
`f.range`, then the **non-unital** subring generated by `x` is
finite. No injectivity, Boolean-ring identities or ambient unit are
needed for this statement.

For a finite Folkman atom stage `A` inside an ambient possibly
non-unital two-sort model, the stage's finite powerset Boolean rings
map by injective non-unital ring homomorphisms into the two ambient
sorts. Hence every tuple contained in that stage has finitely
generated left and right non-unital subrings. A directed-stage atlas
covering every finite tuple implies local finiteness on both sorts.
This is a consequence of its **coverage** hypothesis; neither
common refinements nor ultrahomogeneity is required for finiteness.

The new file
`BANANA/NonPrecompact/FolkmanDirectedFiniteLocalFiniteness.lean`
contains the generic finite-image lemma and its applications to
finite stage witnesses and the atlas. It also constructs genuine
`RingEquiv` witnesses, one for each sort, between the ring generated
by the finite-stage code of a tuple and the ring generated by the
actual tuple in the ambient model.

### Audit route I: containment in a finite range

The range `f.range` is a `NonUnitalSubring` of `T`. It contains
all tuple generators. By the universal property of
`NonUnitalSubring.closure`, it contains the entire generated
non-unital subring:

```
NonUnitalSubring.closure (Set.range x) ≤ f.range
```

The range is finite because it is an image of the finite carrier
`S`. Inclusion of generated closure into this finite range is
injective, establishing finiteness.

The pinned Mathlib API
(`5bd58ac291422a21f412ae354c91e7d172255a2c`,
`Mathlib/RingTheory/NonUnitalSubring/Basic.lean`) explicitly
provides `NonUnitalRingHom.fintypeRange`,
`NonUnitalRingHom.mem_range` and
`NonUnitalSubring.closure_le`. It does **not** require a unit
in either ring.

### Audit route II: exact image of generated closure

The pinned Mathlib identity

```
NonUnitalRingHom.map_closure f U :
  (NonUnitalSubring.closure U).map f =
    NonUnitalSubring.closure (f '' U)
```

shows that the image of the generated closure in a source finite
atom ring is **exactly** the ambient generated closure, not merely a
containing ring. The labelled source generators map to the
labelled ambient generators, so `f '' Set.range(sourceTuple)`
equals `Set.range(ambientTuple)`.

When the finite-stage map is injective,
`NonUnitalSubring.equivMapOfInjective`, followed by
`RingEquiv.nonUnitalSubringCongr`, gives a ring equivalence
between these closures. This is valid for non-unital ring
structures: `RingEquiv` does not require preservation of `1`
in this API. The new
`FolkmanFiniteTupleStageWitness.left_generatedEquiv` and
`right_generatedEquiv` instantiate this in each original
Folkman sort.

Route II is a second, mathematically distinct verification of
the range/closure assertion, but the two routes share Mathlib's
closure interface and **are not independent agent referees**.

### Audit route III: ambient Boolean identities

Every pair of ambient left-sort elements lies in the image of one
finite Boolean atom stage, by applying atlas coverage to a left
tuple of length two and a right tuple of length zero. Since ring
homomorphisms preserve addition and multiplication, every pair
`x,y` satisfies

```
x + x = 0,  x * x = x,  x * y = y * x.
```

The right sort has the same identities by swapping tuple lengths.
No *global* multiplicative identity is inferred. In particular,
the ambient structure is a generalised Boolean ring in this
operation-level sense, rather than an automatically unital Boolean
ring. These source-level lemmas appear in
`FolkmanDirectedFiniteBooleanLaws.lean`.

### Original ambient generated-ring isomorphisms

Equality of full finite tuple profiles yields a ring equivalence of
the **coded** generated subrings on each sort, via the existing
`FolkmanGeneratedTwoSortIso`. Composing with the inverses of
the source stage-to-ambient equivalences and then the target
stage-to-ambient equivalences yields ring equivalences of the
**actual** ambient generated non-unital subrings. The drafted
`FolkmanAmbientGeneratedRingEquivs.lean` packages these two
RingEquiv constructions. They preserve ring operations by type.

**Not yet proved in this module:** the lifted ambient maps
preserve each distinguished generator and the full original
cross-sort pairing. The finite code isomorphism has those
properties, and both stage embeddings reconstruct the pairing,
so there is a precise commuting-diagram proof available.
The required coercion/naturality lemmas and their transitive
axiom audit remain a separate implementation task.

## Counterexamples and edge cases

**Injectivity is essential for an isomorphism.** Let a source ring
have one atom and choose a partial owner map with no target atom
owned by that source atom. Its induced map sends both source
elements to zero. Images of generated subrings are still generated
subrings, but cardinalities differ. This distinction is explicit
in the generic source and the finite regressions.

**No ambient unit should be adjoined.** In a nonzero Boolean
powerset ring with a distinguished zero element, the non-unital
subring generated by the empty tuple is `{0}`. Any unital
closure would force the ambient unit and would give the wrong
age/substructure notion.

**Zero stages and zero sorts.** An atom set may be empty, and
`AsBoolRing (Finset (Fin 0))` is the one-element ring.
The range, non-unital closure, ring equivalence and atlas
arguments remain meaningful without nontriviality assumptions.

**Unused target atoms.** A non-unital embedding may leave
target atoms unowned. Those atoms lie outside the source ring's
image and cannot become generated by its tuple. The image/closure
formula correctly excludes them.

## Independently implemented finite semantic test

A seeded finite powerset-model test, later committed as
`scripts/check_folkman_stage_generated_closures.py`,
passed the following cases in the local Python runtime:

- 332 sampled/exhaustive partial owner maps on 0–3 source atoms
  and 0–4 target atoms;
- 23,441 labelled finite source tuples;
- 6,895 injective transport instances (ring operations checked);
- 16,546 non-injective transport instances (image-of-closure
  equality checked, with no false isomorphism claim).

Every case checked `f(generated(xs)) = generated(f(xs))` and
containment in the finite map range. The test explicitly checks
that an owner map with an empty source fibre is non-injective.
This is **finite semantic regression, not a Lean kernel check**.
It has an optimised-Python refusal guard and is included in the
local exact-head verification script.
